# Implementation Plan: Refactor Configuration to UI/Env

## Objective
Centralize all service-level configuration (ports, timeouts, MQTT broker, metrics toggles) into the Home Assistant Add-on UI (and environment variables for standalone users).
Reserve the YAML configuration file **strictly** for defining the array of ECHONET devices. This resolves the "split brain" configuration issue and prevents complex YAML syntax
errors for basic settings.

## Proposed Changes

### 1. Add-on Configuration (`addon_echonetgo/config.yaml`)
- **Remove**: `config_path` from `options` and `schema`.
- **Add**: `devices_path: "/config/echonetgo/devices.yaml"` as the new primary file reference.
- **Add to Schema & Options**:
  - `listen_addr: "0.0.0.0:9191"`
  - `scrape_timeout_sec: 15`
  - `strict_source_port_3610: true`
  - `metrics_enabled: true`
  - `notifications_enabled: true`
  - `force_polling: false`
  - `multicast_interfaces: ""` (comma-separated string)

### 2. Add-on Boot Script (`addon_echonetgo/rootfs/run.sh`)
- Use `jq` to read all the newly added schema fields from `/data/options.json`.
- Export them as their corresponding `ECHONET_*` environment variables (e.g., `export ECHONET_METRICS_ENABLED=$(jq -r '.metrics_enabled' ...)`).

### 3. Go Backend (`internal/config/config.go`)
- **Remove**: The entire `fileConfig` struct, `ConfigPath` field, and the `loadFromFile` function. The Go app will no longer attempt to parse service configuration from a YAML
file.
- **Update Defaults**: Default `DevicesPath` to `etc/devices.yaml` (if `ECHONET_DEVICES_PATH` is not set).
- **Simplify `Load()`**: The loading sequence will now purely apply default values, override them with environment variables via `applyEnvOverrides()`, and then load the
`devices` array via `loadDevicesFile(cfg.DevicesPath)`.

### 4. Renames & Documentation
- **Rename**: `etc/config.example.yaml` to `etc/devices.example.yaml`.
- **Strip**: Remove all top-level keys except `devices:` from the example file.
- **Update**: `addon_echonetgo/DOCS.md` and `README.md` to reflect that `config.yaml` is now `devices.yaml`, and that all other configuration is managed via the UI or
environment variables.

## Verification
- Validate the new Add-on schema loads correctly in the Home Assistant UI.
- Verify `run.sh` correctly maps UI selections to environment variables.
- Ensure the Go application boots and loads the `devices:` array from `/config/echonetgo/devices.yaml`.
- Ensure tests in `config_test.go` are updated to match the new loading flow.
